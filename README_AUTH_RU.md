# Вышка саппортов — Discord OAuth2 и белый список

## Что уже добавлено в проект
- Сервер Node.js/Express; сайт отдаётся с `/` только после проверки серверной сессии.
- Настоящий OAuth2 Discord (`identify`), обмен кода выполняется на сервере, `state` одноразовый.
- Сессии хранятся в PostgreSQL, cookie `HttpOnly`, `SameSite=Lax`, в production — `Secure`.
- Белый список и роли в PostgreSQL; сервер повторно проверяет членство и роль для защищённых API.
- Первый администратор задаётся только через `BOOTSTRAP_ADMIN_DISCORD_ID`; первый вошедший пользователь администратором не становится.
- Администратор управляет белым списком из «Настройки»; доступна выдача/смена роли, поиск, удаление. Удаление немедленно блокирует следующие запросы и делает текущую сессию недействительной.
- Убрано переключение демо-роли в шапке; отображаются Discord-имя, аватар и серверная роль.
- Текущий интерфейс и существующие разделы сохранены.

## Важное ограничение текущего этапа
Данные рабочих разделов исходного сайта (состав, задания, таблицы, события и т. п.) пока остаются в старом `localStorage` и НЕ превращены в общую базу. Это означает, что они не синхронизируются между пользователями/устройствами, а сами изменения этих разделов пока не проходят через отдельные серверные API с проверкой разрешений. Поэтому проект не следует считать полностью готовой к production системой управления данными, пока не будет выполнен следующий этап — перенос данных сайта в PostgreSQL и перевод CRUD каждой сущности на защищённые API с матрицей прав.

## Запуск локально
Требуются Node.js 20+ и PostgreSQL.

1. Скопируй `.env.example` в `.env`.
2. Заполни `DATABASE_URL`, `SESSION_SECRET`, `DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET`, `DISCORD_REDIRECT_URI`, `BOOTSTRAP_ADMIN_DISCORD_ID`.
3. В Discord Developer Portal создай Application → OAuth2. Скопируй Client ID и Client Secret. В Redirects добавь точное значение `DISCORD_REDIRECT_URI`, например `http://localhost:3000/auth/callback` для локального тестирования.
4. Для локального HTTP теста установи `NODE_ENV=development`, `DISCORD_REDIRECT_URI=http://localhost:3000/auth/callback`; для публичного сайта используй HTTPS и `NODE_ENV=production`.
5. В Discord настройках приложения разреши scope `identify` (он запрашивается OAuth2-ссылкой автоматически).
6. Установи зависимости: `npm install`.
7. Запусти `npm start` и открой `http://localhost:3000`.
8. Значение `BOOTSTRAP_ADMIN_DISCORD_ID` должно быть Discord ID твоего аккаунта. Включи Developer Mode в Discord → профиль пользователя → Copy User ID. При старте сервер добавит этот ID администратором только если записи ещё нет.
9. Войди этим аккаунтом и добавь Discord ID остальных пользователей в «Настройки» → «Белый список».

## Хостинг
Нужен хостинг Node.js с постоянными environment variables и PostgreSQL (например, Render/Railway/Fly.io + managed PostgreSQL). Обычный статический Netlify Drop не запускает этот backend как есть. На хостинге:
- укажи команду запуска `npm start`;
- задай все переменные из `.env.example` в панели хостинга;
- настрой HTTPS;
- впиши публичный адрес `/auth/callback` в Discord Developer Portal и `DISCORD_REDIRECT_URI`;
- не загружай настоящий `.env` в репозиторий;
- не публикуй `DISCORD_CLIENT_SECRET` в клиентском JavaScript.

`schema.sql` содержит эквивалентную схему таблиц; `server.js` также создаёт необходимые таблицы при старте.
